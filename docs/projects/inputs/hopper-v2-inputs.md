# DW Hopper V2: form inputs

*Read from `DriveWorks Files/Hopper/DW Hopper V2.driveprojx` as saved 2026-09-09 13:42. Written 2026-10-02 for Bruno's pre-sales layout app, which should use the same parameters as DriveWorks.*

This table lists every input on the DW Hopper V2 form, the bolted-panel loading hopper that sits on a conveyor, so the layout app can use the same parameter names.

- **DriveWorks Input**: the control name exactly as it appears in DriveWorks.
- **Description**: what the input is for, inferred from its caption, options and rules.
- **Group**: the form page the input sits on.
- **Limitation**: minimum, maximum, option list, or an override limit set by a rule. Empty when there is none.
- **Layout effect**: what the input changes in the hopper's size or position in a layout. Empty when it changes neither.

## Inputs

Rows follow the form from top to bottom: the sections the left window stacks (CustomerInfo, GeneralInfo, DropZoneSideInfo, DropZoneBackInfo, MidSectionInfo, then the Development-only Tables and ForDevOnly), then the two check boxes beside the Release button. Right and left twins share a row; the left box is hidden and copies the right one when Same Left Side As Right Side is on. ## How Hopper V2 builds the drop-zone panels

V2 is the parent of DW Hopper V2 - Panels ([hopper-v2-panels-inputs.md](hopper-v2-panels-inputs.md)). V2's own model, `DW09B-Hopper Main Assembly`, holds the transition, mid, elbow and after-elbow kits as parts. Every drop-zone panel is a separate Panels spec.

- **The panel grid.** Each side is a grid of kits K`cr`: column c = 1–4 along the conveyor, row r = 0–2 up the wall (picture `Right Side DropZone Dim Viewer.png`). The back has one column of rows K10–K12, or two columns (K20–K22 and K30–K32) when its top width (right + left half-widths above the offsets) is over 48 in, when only one side has an offset, or when the two offsets differ in height. Panels are at most 36 in high (`PanelMaxHeight`) and 48 in long (`PanelMaxLength`).
- **Assembly numbers.** Right side A32, left side A31, back A30. File names are `<prefix>-A32-K<nn>-<colour code>-YD`, a yard (site-assembled) kit.
- **The list.** Calc table `DropZonePanelList` has one row per possible panel (12 right, 12 left, 9 back) with an Enable flag: the panel's row and column exist, and for a side with an angled top cut, the panel starts below the cut line. `CleanPanelListTable` keeps the enabled rows.
- **The release loop.** On entering Completed, macro `ReleaseAllPanels` runs `ReleaseAllPanelsSub` once per enabled panel (`NumberOfLoopPanels`). Each pass sets `PanelSelectorSpinButton` to the counter, loads DW Hopper V2 - Panels into `SinglePannelHostControl`, and runs the child's `Release` macro. The host's InputValues are the Name/Value calc table `PanelListInput` (64 rows), so each child spec gets that panel's values. Then V2 releases its documents, emails and models.
- **Putting the panels in.** The top-level assembly has dummy instances (`DW09B-Right Side Drop Zone Assy Dummy-1` … `-12`, left `-1` … `-12`, back `-1` … `-9`). Each one is replaced by `<prefix>-A3x-K<nn>-<colour code>-YD-with Onsite Bolts.sldasm` from the output folder, or deleted when its panel is off. The plane dimensions `K11/K12 Y Plane`, `K20/K30/K40 Z Plane` and `K11/K12 Z Plane` place them at the row heights, column lengths and back-lean offsets.
- **Who sees it.** The host and its buttons sit on the Tables page, which only the Development team sees. Any user's release still builds every panel.

## Size and position in a layout

- **Units:** inches in the model; the lengths are typed in feet.
- **What it mounts on:** a conveyor, picked by Conveyor Type. The bottom-row panels get a bottom flange 5.5 in wide (Kit or Other), 4.5 in (Light Duty) or 2.875 in (Picking). There are no legs or supports, and no DW Start Leg host.
- **Position on the conveyor:** no input places the hopper. The model starts at the foot of the back wall, which faces the tail. The layout has to place it on the conveyor itself.
- **Incline:** the model is drawn along the conveyor bed and has no incline of its own, so in a layout it tilts with the conveyor. Conveyor Angle only sets the upper back panels plumb.
- **Length along the conveyor:** Before Elbow Length × 12 + adjustment, plus After Elbow Length × 12 (+6 in on a Kit Conveyor) with an elbow. Adjustment: −1 in Kit, −1.6875 in Light Duty, +0.25 in Picking, 0 Other. A Backward back angle adds (end height − start height) / tan(angle) behind the back wall's foot.
- **Inside width:** at the bottom, belt − 6 in (Kit), belt + 0.65 in (Light Duty), belt (Picking), or Inside Width (Other), centred on the conveyor. In the drop zone, a side with an offset is wider by its offset width above the offset top. The plate thickness and flanges add to the outside; no variable computes the outside width.
- **Heights (above the bottom of the walls):** drop-zone sides up to 108 in (or offset top + 72 in), back wall as typed, transition kit at Transition Piece Height, then Mid Hopper Panel Height along the rest of the conveyor. An angled top cut lowers a side toward the head.
- **Inlet:** the open top of the drop zone, Drop Zone Length long and as wide as the drop zone, closed at the tail by the back wall.
- **Outlet:** the hopper is open at the bottom onto the belt and open at the head end. There is no discharge height or chute: `Chute` and `Covers` do nothing yet.

## Notes and open questions

- **Who counts as a Sparta user.** The form tests `IsUserInEngineering` (Engineering or Xortion Engineering) for the work-order fields, WO Prefix, the colour codes and High Priority, and `IsUserInDevelopement` for the Tables and ForDevOnly pages and Dev Release. Every geometry page is shown to all users. In practice the hoppers are Engineering-only, since other users reach only Kit Conveyor and the platform projects through Sparta's website access.
- **How it is opened.** On its own. The constant `OpennedFromOrderProject` is False, and DW Order Project doesn't name the hopper, so the "opened from Order" branches never apply. In the sandbox group V2 is visible and `Deployed=False`; DW Hopper V2 - Panels and the original DW Hopper Project are hidden, also `Deployed=False`.
- **The original DW Hopper Project** ([hopper-inputs.md](hopper-inputs.md)) is a separate design: DW09 models in `Models`, with overall inputs such as `HopperWidth`, `HopperLength` and `HopperHeight`. V2 uses DW09B models in `Models V2`, inputs per side and per section, and bolted panel kits. Neither project names the other.
- **Unreachable controls.** The CustomerInfo frame is 600 px wide with its scroll bars hidden, and Equipment Name, Sticker Name and Safety Parts Color sit at 748 px. So Equipment Name stays empty, and the file-name prefix is WO Prefix. When WO Prefix is also empty, the prefix falls back to `DWVariableClientTeamName`, which doesn't exist in this project.
- **No default is set** for Hopper Thickness, Conveyor Type, Etching Type, Back Angle Direction, Paint Color, Client and Project. Every numeric box defaults to 0, so a new spec starts with no lengths or heights. **Defaults below the minimum:** the bottom bend heights (0, min 2.5) and the transition heights (0, min = Mid Hopper Panel Height).
- **Caption limits that aren't enforced:** Offset Width "min 4in", Back Height "min 6, max 90" and Start Of Back Angle "min 2.5" all allow 0–100.
- **Drop zones over about 16 ft.** A side has only four panel columns of at most 48 in, but Drop Zone Length allows 100 ft, and nothing checks it against Before Elbow Length either. Sparta engineering should confirm the real limits.
- **The top-cut angle reaches the panels even when the cut is off.** `PanelListInput` sends `AngledTopCut<side>SideDeg` through `Indirect`, without testing the check box. It matters only if a value was typed before the box was turned off.
- **Inputs with no effect:** Covers, Chute, Sticker Name, Safety Parts Color, Designer Drafter, and the three ForDevOnly output switches.
- **Exports.** There is no SQL table. On release, Completed releases every document: the `NewClientProjects` export (client, project, work order and prefix to the ClientProjects group table, on every release), an email to the user with `00- <prefix>-Hopper.pdf`, and a tracking email to an admin address. Files go to `\\192.168.0.19\Driveworks Output Files\<prefix>-Hopper <spec id as 0000>`.
- **Possible folder mismatch, to check on a real release.** V2 looks for the panel files in its own folder, `<prefix>-Hopper ` + `Text(id, "0000")`. Panels builds its folder from `HostedSpecificationId` without that format, so for spec IDs below 1000 the two folder names would differ.
